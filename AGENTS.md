# AI usage rules for the M324 team project

These rules apply to all AI assistance in this repository. They follow the M324 KI-Nutzungsrahmen.

## Responsibility
- You own all code, tests, pipelines, deployments, processes and documentation you commit.
- Only commit changes you can explain in the team review or code walkthrough.

## Allowed
- Explaining DevOps concepts, error messages, test types, pipeline steps and deployment strategies.
- Comparing options, for example GitLab CI vs. GitHub Actions, or Blue/Green vs. Canary.
- Suggesting tests, edge cases, review questions and monitoring metrics.
- Debugging hypotheses, which you verify yourself.
- Improving the wording of your own documentation, while the content and decisions stay yours.

## Not allowed
- Generating a complete deliverable that you do not understand.
- Inventing logs, test results, pipeline output or sources.
- Entering passwords, tokens, private keys, customer data or personal data into AI tools.

## Verification
- Check every AI suggestion with tests, CI/CD logs, local commands, reviews or official documentation.
- Do not treat a second AI answer as proof.

## Documentation
- When AI was used for a deliverable, add a short "KI-Nachweis" to the project documentation with: tool, purpose, your own starting plan, key AI output, what you accepted, changed or rejected, how you validated it, and your own decision.
- If no AI was used, state that.
